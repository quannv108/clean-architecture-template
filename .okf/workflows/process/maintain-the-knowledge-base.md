# Maintain the Knowledge Base

`.okf/` is an [Open Knowledge Format](https://github.com/GoogleCloudPlatform/open-knowledge-format) v0.2
bundle, adopted in [ADR 0015](../../adr/0015-adopt-okf-knowledge-base.md). A concept file that disagrees with
the code is a defect, and a knowledge base that is confidently wrong is worse than none — so every code change
that teaches you something updates `.okf/` **in the same commit**. Agents: the `open-knowledge-format` skill
(`.claude/skills/open-knowledge-format/`) is the authoring guide; this page is what that skill does not know
about this bundle.

## Steps

1. **Find the directory** whose question your fact answers (the root [index](../../index.md) lists them).
   Do not add knowledge to `AGENTS.md`, `README.md` or a code comment.
2. **Copy the directory's `_template-*.md`** (or [domains/_templates/](../../domains/_templates/index.md)),
   replace everything, and write the one-sentence `description` first — if it needs an "and", you have two
   concepts.
3. **Link, don't copy.** A fact lives in one file; every other file links to it with the target's `title` as
   the link text. Links are **relative** (`../x.md`), never a bare path as the label.
4. **Add the file to its directory's `index.md`** under the section it belongs to, as

   ```markdown
   * [Title](file.md) - description
   ```

   The description must equal the file's frontmatter (`--fix` below does this for you).
5. **Add a line to [Knowledge Base Update Log](../../log.md)** under today's `## YYYY-MM-DD` heading, newest
   first.
6. **Run the checker** and fix everything it reports:

   ```bash
   python3 .okf/tools/okf.py          # check, sync index entries, regenerate map.md
   python3 .okf/tools/okf.py --fix    # also rewrite drifted index descriptions and append unlisted files
   python3 .okf/tools/okf.py --check  # what the pre-commit hook and CI run
   ```

## Bundle conventions

* **`index.md` and `log.md` are reserved** and never concepts. `index.md` has no frontmatter (the root
  carries only `okf_version`) and is a listing: `#` sections of `* [Title](link) - description` bullets, with
  at most a short lead paragraph. Guidance longer than that belongs in a concept file.
* **`type` vocabulary** is the `# Concept types` list in the root [index](../../index.md); the checker
  rejects anything else. Add a value there before using it; never a near-synonym of an existing one.
* **A domain slice's concept file is `domains/<slice>/<slice>.md`** (`type: Domain Slice`); the slice's
  `index.md` lists it first.
* **`resource:`** on a concept that maps to code is the repository-relative path of that code. Trust the file
  over the prose, and fix the prose.
* **Provenance.** Unless a file says otherwise, everything here was generated by `anthropic/claude-opus-5` on
  2026-09-19 from the repository's previous `docs/` tree and its source, and has **not been human-verified**.
  Add `verified: { by: human:<id>, at: <ISO8601> }` to a file once you have checked it against the code.
* **Deprecate rather than delete.** Set `status: deprecated` and say what replaced it, so an agent following
  an old link learns something instead of hitting a dead end.
* **Templates** (`_template-*.md`, `domains/_templates/`) are blanks to copy; they are how this template grows
  into a real project — see [Extending the Template](extending-the-template.md).
* **[Bundle Map](../../map.md)** is generated — never edit it by hand.

## Which directory, and what goes there

| You learned | Put it in | Notes |
|---|---|---|
| Why a choice was made | [adr/](../../adr/index.md) | Write an ADR when the decision is expensive to reverse, when a reasonable engineer would choose otherwise, or when you have explained the reasoning twice. **Supersede rather than edit** — an accepted ADR records what was believed at a point in time. |
| A naming, placement or style rule | [conventions/](../../engineering/conventions/index.md) | A convention mainly needed *an* answer applied consistently. If real alternatives were weighed, it is an ADR. |
| A rule the architecture tests enforce | a row in [Constraints](../../engineering/constraints.md) | The row names the rule, the test and the owner page; the *why* lives on the owner, never in the table. If a rule is wrong, change the decision first (ADR), then the test and the code together. |
| How a mechanism works end to end | [cross-cutting/](../../architecture/cross-cutting/index.md) | Explains the moving parts and why they are arranged that way. |
| How to *write* one more of something | [patterns/](../../engineering/patterns/index.md) | Copyable code and a checklist. When a cross-cutting page and a pattern cover one subject, the cross-cutting page links to the pattern rather than repeating the code. |
| A new external dependency | [technologies/](../../engineering/technologies/index.md) | Versions are centrally managed in `Directory.Packages.props` — never pin one in a `.csproj`. Wrap the library behind an abstraction in `Application/Abstractions/`, add a file here, and write an ADR if the choice was not obvious. |
| What a type is | nowhere - link the `.cs` | The code is the concept. Link it with a relative path (the checker verifies it exists); the owning [component](../../architecture/components/index.md) page lists a layer's files. A page that only restates a class is a defect. |
| A business entity, value object or slice | [domains/](../../domains/index.md) | One folder per slice: `<slice>.md`, one file per entity and value object, `<entity>-errors.md`. Then follow [Add a Feature](../engineering/add-a-feature.md) for the code. |
| A word a new reader would pause on | [glossary/](../../glossary/index.md) | Copy [Term Template](../../glossary/_template-term.md); the first tag is the subject and picks the `#` section of the index. If the entry needs more than a screen it is a pattern or an architecture concept, and the term should link there. Your product's own terms belong here too. |
| A repeatable procedure | [workflows/](../index.md) | `engineering/` for build, run, test, migrate; `process/` for branching, PRs, growing the template. |
| A known gap or planned work | [backlog/](../../backlog/index.md) | `type: Task`, `status: draft`; state the problem before the proposal. When done, delete the file and log it — a backlog of completed items is noise. If it turns out to be a decision, promote it to an ADR. |

## The commit gate

`.githooks/pre-commit` runs `okf.py --check` whenever a staged file is under `.okf/`, so a broken bundle
cannot be committed (it also runs `dotnet format` on staged `.cs` files - [Format Code](../engineering/format-code.md)). Git only honours it when `core.hooksPath` points at `.githooks`; the `InstallGitHooks`
target in `Directory.Build.props` sets that on every `dotnet build` / `dotnet test`, so a fresh clone is
covered as soon as it builds. To set it without building:

```bash
git config core.hooksPath .githooks
```

CI runs the same command, so a bypass with `--no-verify` still fails the pull request.

## Verify

* `python3 .okf/tools/okf.py --check` exits 0.
* The new file appears in [Bundle Map](../../map.md) with the right type and description.
* `dotnet test tests/ArchitectureTests/` still passes if the change touched a constraint.
